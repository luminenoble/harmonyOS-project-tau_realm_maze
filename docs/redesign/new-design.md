# TauRealmMaze — 新设计方案

> 本文档记录对原始设计的重构思路，供开发阶段参考。

---

## 一、核心概念重定位

### 玩家身份

| 原设定 | 新设定 |
|--------|--------|
| 一段数据包 | **控制信号（Control Signal）** |

玩家是 CPU 控制单元（Control Unit）发出的控制信号，负责协调寄存器、ALU、缓存之间的数据流动。  
"收集碎片"的本质是**执行一条机器指令**（如 `LOAD eax, [addr]`）；"到达终点"的本质是**完成写回（Write Back）**，整条指令序列构成一次完整的 CPU 数据通路执行。

---

## 二、关卡结构：指令序列驱动

### 2.1 AI 生成指令序列（DeepSeek API）

每局开始前，玩家选择难度，客户端向 DeepSeek API 发送请求，生成一段**合法的、可执行的汇编指令序列**，描述一个具体的运算任务（如向量内积、位掩码提取、累加求和等）。

**难度与指令数量对应：**

| 难度 | 指令数 | 每层最大并行指令数 | 典型运算场景 |
|------|--------|-------------------|-------------|
| Easy | 9 条 | ≤ 2 | 两数相加并写回 |
| Normal | 12 条 | ≤ 3 | 1×2 向量内积 |
| Hard | 15 条 | ≤ 4 | 位运算 + 条件累加 |

**Prompt 约束模板（发送给 DeepSeek）：**

```
你是一个 x86 汇编教学助手。请生成一段 {N} 条指令的合法汇编序列，要求：
1. 只使用以下指令集：LOAD、STORE、MOV、ADD、SUB、MUL、AND、OR、XOR、SHL、SHR
2. 只使用寄存器：eax、ebx、ecx、edx、esi、edi（最多使用其中4个）
3. 序列必须描述一个有意义的运算（如内积、掩码提取、求和），并以 STORE 写回一个结果寄存器结尾
4. 每条指令附带一行中文注释说明其作用
5. 不要出现：浮点指令、跳转指令（JMP/JE等）、栈操作（PUSH/POP）、系统调用
6. 返回格式为 JSON 数组，每项包含 index（序号）、mnemonic（指令助记符）、operands（操作数字符串）、comment（注释）、depth（该指令在依赖图中的深度，从0开始）
7. 操作数依赖图（DAG）中，同一 depth 的指令数不超过 {MAX_WIDTH} 条（Easy=2 / Normal=3 / Hard=4）
```

API 返回结果后，游戏解析 JSON，按依赖关系将碎片分配到地图各层。

### 2.2 加载界面：终端风格

等待 API 返回期间，显示终端风格加载界面：

```
> Connecting to DeepSeek API...
> Generating instruction sequence [Normal / 9 ops]...
> [████████░░] 80%
> Parsing operand dependency graph...
> Allocating fragments to layers...
> Map render complete.
```

API 返回后，指令逐行滚动打印，随后切入地图渲染动画（电路走线逐格生成）。

## 三、碎片系统重设计

### 3.1 碎片类型与皮肤

| 碎片类型 | 外观皮肤 | 含义 |
|----------|----------|------|
| 寄存器碎片 | 蓝色芯片图标，标注 `eax`/`ebx`/`ecx`/`edx`/`esi`/`edi` | 对应一个寄存器的当前值 |
| 立即数碎片 | 金色标签，标注 `#5`/`#FF` 等 | 硬编码操作数 |
| 内存地址碎片 | 橙色方块，标注 `[addr]` | 内存取值目标地址 |

收集碎片 = 执行对应指令（`LOAD`/`MOV` 等），碎片消失，HUD 的"持有寄存器"状态更新。

### 3.2 障碍块：ALU 运算门

场地中放置运算障碍块，需持有**特定操作数碎片组合**才能通过：

| 障碍类型 | 通过条件 | 对应指令 |
|----------|----------|----------|
| `ADD` 门 | 持有两个源寄存器碎片 | `ADD eax, ebx` |
| `MUL` 门 | 持有两个源寄存器碎片 | `MUL ecx, edx` |
| `AND`/`OR`/`XOR` 门 | 持有对应操作数 | 位运算指令 |
| `SHL`/`SHR` 门 | 持有寄存器 + 立即数碎片 | 移位指令 |

通过障碍时触发动效：ALU 闪光，结果寄存器碎片在玩家位置生成（替换消耗的源碎片）。

### 3.3 数据冒险障碍（进阶）

场地中偶尔出现 `RAW`（读后写）危险格，踩上后当前持有的某个寄存器碎片失效，需重新取。模拟流水线数据冒险。

## 四、VIA 块重设计

### 4.1 交互皮肤

| 行为 | 显示文本 | 说明 |
|------|----------|------|
| 走上 VIA | `CALL` | 模拟函数调用 / 跨层跳转 |
| 离开 VIA（返回） | `RET` | 模拟函数返回 |

### 4.2 缓存延迟保留

VIA 的缓存语义不变，仅皮肤更新：

| VIA 类型 | 颜色 | 延迟（时钟周期） | HUD 提示 |
|----------|------|-----------------|----------|
| L1-VIA | 金色 | 1 | `L1$ HIT — 1 cycle` |
| L2-VIA | 银色 | 3 | `L2$ HIT — 3 cycles` |
| MEM-VIA | 铜色 | 6 | `DRAM ACCESS — 6 cycles` |
| THERMAL_VIA | 青白 | 0（降热） | `PIPELINE FLUSH` |

## 七、结算页更新

τ 值重定义为 **CPI（Cycles Per Instruction）**：

```
CPI = (移动步数 + 所有 VIA 延迟累计) / 总指令数
```

| 评级 | CPI 阈值 | 描述 |
|------|----------|------|
| S | ≤ 1.2 | 超标量理想执行 |
| A | ≤ 2.0 | L1 全命中 |
| B | ≤ 4.0 | L2 部分命中 |
| C | > 4.0 | 频繁主存访问 |

**AI 结算评语 Prompt 模板（DeepSeek）：**

```
你是一位 CPU 微架构工程师，正在 review 一条指令序列的执行轨迹。
指令类型: {instrType}（如"1×2向量内积"）
总指令数: {totalInstr}
移动步数: {steps}
缓存命中: L1×{l1} / L2×{l2} / DRAM×{mem}
数据冒险触发次数: {hazards}
最终 CPI: {cpi}

请用芯片工程师的口吻，简短评价这次执行效率并给出一条优化建议。不超过80字。
```

## 八、地图参数更新（19×19）

### 8.1 地图尺寸

| 参数 | 原值 | 新值 | 说明 |
|------|------|------|------|
| 网格尺寸 | 13×13 | **19×19** | 逻辑格 9×9（奇数格=通道，偶数格=墙） |
| 可用通道格/层 | ~36 | **~81** | 空间余量大幅提升 |
| 单格像素（等距） | ~48px | **36px** | 平板横屏内仍完整可见 |
| VIA 节点数/层 | 3-4 | **3-4**（不变） | 空间更大但保持稀疏感 |
| THERMAL_VIA 数/层 | 2-3 | **2-3**（不变） | |
| RAW 危险格数/层 | — | **1-2**（新增） | |
| 信号碎片数/层 | 3 | **按难度 2/3/4** | 与每层最大并行指令数对齐 |

### 8.2 散热系统参数更新

原设计使用单一积热速率（底层×2），新设计改为**三层独立积热速率**，比值 4:3:2（Layer 0 最快），阈值统一下调以适配更大地图的更多步数。

| 参数 | 原值 | 新值 |
|------|------|------|
| 减速阈值 | 80 | **60** |
| 强制降层阈值 | 100 | **90** |
| Layer 0 积热速率/步 | +2（×2倍率） | **+2** |
| Layer 1 积热速率/步 | +1（×1倍率） | **+1.5** |
| Layer 2 积热速率/步 | +1（×1倍率） | **+1** |

各层预计触发步数（无散热道具干预）：

| 层 | 触发减速（60）| 触发强制降层（90）|
|----|--------------|-----------------|
| Layer 0（器件层） | ~30 步 | ~45 步 |
| Layer 1（缓存层） | ~40 步 | ~60 步 |
| Layer 2（互联层） | ~60 步 | ~90 步 |

层间积热速率比值 2:1.5:1 ≈ **4:3:2**，满足设计要求的 Layer 0:1:2 = 2:3:4 过热耐久比（速率越高 → 越快过热 → 耐久越低）。

需修改：`game/core/HeatManager.ts` 的阈值常量与分层速率配置。
